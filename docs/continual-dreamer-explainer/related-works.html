Continual Model-Based Reinforcement Learning · Problem and Baselines

持续世界模型：
问题、方法与基线

先不谈 MoE、冻结 Encoder 或 Actor rehearsal。这里先把同一个问题说清楚：在固定资源、没有 task ID 的顺序任务中， Dreamer 为什么会在旧任务掉分；Continual-Dreamer 和 ARROW 分别实际改变了什么。

协议：顺序、task-agnostic 资源：固定 replay / updates 对象：WM + Actor-Critic 目标：旧任务回报保持

一句话

Continual-Dreamer 和 ARROW 都先回答“有限 memory 里如何让旧数据继续被看见”；它们并没有直接证明 世界模型、Critic、Actor 中究竟是谁造成旧回报下降。这正是我们后续方法之前必须先做的诊断。

01

Problem

我们到底在解什么问题

给定按顺序到来的任务 M1, ..., MT，agent 在任务 t 期间只能和当前环境交互。任务切换后，旧环境不可再采样；模型和策略也不接收 task ID。 它只能保留一个总容量固定的 replay buffer，并用其中的数据持续更新同一套 Dreamer 参数。

Dt → Bt = U(Bt-1, Dt),   Bt → (θWM, θActor, θCritic),   maximize (1/T)Σi=1T Ji(θT)

公平比较至少固定四件事：每任务交互步数、世界模型和 Actor-Critic 的更新次数、总 replay 容量及实际字节数、评估日程。 不然“更不忘”可能只是存得更多、训练得更久，或者用了 task 标签。

层次真正的问题仅看最终旧任务 return 能否回答
数据层固定 memory 下，哪些旧轨迹还应留在训练分布里？不能；它只告诉我们结果，不告诉我们哪类轨迹缺失。
模型层旧动力学、reward、continuation 或表征是否漂移？不能；旧策略失效不等于世界模型一定忘了。
控制层在仍可用的 latent model 上，Critic 或 Actor 是否已不能恢复旧行为？不能；同一掉分可由 Actor、Critic 或 imagined-state 分布改变造成。
研究边界。 回放策略首先改变的是训练数据分布；它不是对任何一个网络模块的直接保护。因而“回放有效”与“世界模型不忘”是两句话，不能混为一句。
02

Continual-Dreamer

先证明 world model 是持续 RL 的强基线

Continual-Dreamer 建立在 DreamerV2 上。DreamerV2 用 replay 中的真实轨迹训练 RSSM world model， 再在 latent imagination 中训练 Actor 和 Critic。该工作把 replay 跨任务保留，并系统比较 buffer 的写入和采样策略； 最终把 reservoir sampling 的 DreamerV2 称为 Continual-Dreamer。带 world-model uncertainty exploration 的版本称为 Continual-Dreamer + Plan2Explore。整个方法不向网络输入 task ID。 [论文]

项目Continual-Dreamer 的选择它回答了什么它没有回答什么
骨干DreamerV2；WM 与 Actor-Critic 仍端到端更新像素 world model 能在 task-agnostic CRL 中成为有效 agent掉分时哪个模块先失效
记忆跨任务 persistent replay；主配置用 reservoir sampling 保持历史覆盖FIFO 会逐渐挤掉早期任务；reservoir 可缓解 forgetting哪些保存的轨迹对控制最关键
探索可加 Plan2Explore 的 intrinsic reward世界模型的 uncertainty 可帮助新任务探索探索改善是否也等于旧技能保持
环境MiniGrid 与 MiniHack 的顺序图像任务在这些稀疏奖励任务上可兼顾学习与保留结论是否迁移到 Atari / DreamerV3 / 不同预算

它比较的 baseline 是什么？

类别论文中的对照比较意图
原始 world-model 基线DreamerV2；DreamerV2 + Plan2Explore先看不做 selective replay 的 Dreamer 是否能持续学习。
task-agnostic CRL 基线CLEAR；IMPALA与当时不依赖 task identity 的持续 RL 方法比较学习、forgetting 与 transfer。
replay 消融FIFO、reservoir、coverage maximization、uncertainty / reward sampling、50:50 recent-history sampling、增大 buffer分开检查 buffer 如何写入和 minibatch 如何组成。
task-aware 上界/对照围绕上一任务最优参数的 L2 regularization说明给 task-aware 正则并不自动优于 task-agnostic replay。
该文的核心贡献：它不是提出一个新 RSSM，而是把 DreamerV2 + reservoir replay 确立为 task-agnostic continual RL 的强模型化基线。 它的结论是“这样配 replay 在其任务上更好”，不是“world model 因此本质不会忘”。
03

ARROW

在同一 DreamerV3 上，只重做 replay 分配

ARROW 的骨干是 DreamerV3。它不把 Actor-Critic 改成额外的持续学习算法，也不把 world model 换成 MoE； 直接贡献是 Augmented Replay：在同一总 memory 下并存一个短期 FIFO 和一个长期 LTDM buffer，并从两者抽取数据训练 DreamerV3 world model。Actor-Critic 仍通过 world model 的 imagined rollouts 学习。 [论文]

B = BFIFO ∪ BLTDM,   |BFIFO| + |BLTDM| = Btotal
项目ARROW-50 主设置作用不改变的部分
FIFO总 trajectory 容量的一半高密度保留最近任务数据，保持适应新任务的 plasticityEncoder、RSSM、reward/continue head 与 Actor-Critic 架构
LTDM总 trajectory 容量的一半以长期、近似均匀的历史覆盖避免早期任务完全消失世界模型 loss 与 imagination actor-critic 训练范式
采样FIFO / LTDM 各 0.5 的 minibatch 来源概率同时保留 current adaptation 和 historical rehearsal不输入 task ID；不直接给 Actor 加 behavior cloning target
评估Atari 的无共享任务与 CoinRun variants 的共享结构任务分别看 retention 与 possible transfer不能从总 return 单独定位 WM、Critic 或 Actor

它比较的 baseline 是什么？

对照和 ARROW 的关系应该怎样读
DreamerV3 / FIFO同一个 DreamerV3 backbone，只保留固定大小 FIFO replay这是最关键的 matched model-based baseline：隔离“混合 replay 分配”本身的作用。
TES-SAC模型无关 continual RL baseline比较模型化路线与 model-free replay/controller 路线，不用于定位 Dreamer 内部模块。
AR25 / AR75FIFO / LTDM 的 25:75、75:25 容量与采样比例消融它们是 ARROW 的 memory-allocation ablation，不是独立外部 baseline。
ARROW 的贡献：在不改变 DreamerV3 核心网络、不给 task ID、且匹配总 replay 容量的前提下， 用“近期 + 长期”的 replay 分布处理 stability-plasticity。它提供的是一个非常干净的 data-distribution baseline， 不是模块级遗忘机制的答案。

因此我们的起点不是“再发明一种存样本”，而是：在 ARROW 的固定预算与 task-agnostic 协议下， 先区分历史数据覆盖不足、world-model 预测漂移、Critic 失准和 Actor 行为遗忘。只有诊断稳定后， 才决定该做 replay、rehearsal，还是条件化容量。

当前可检验假设。 若替换回旧 world model 就恢复旧任务，而新 Actor 不行，才有理由研究 Actor-specific rehearsal；若新 world model 已无法提供旧任务所需预测， 则应先改 memory / representation / dynamics，而不是直接上 MoE。
