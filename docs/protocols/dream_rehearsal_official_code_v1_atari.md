## Status and claim boundary

Implemented on 2026-09-05. Deterministic CPU source/boundary fixtures pass;
target-CUDA smoke, full Atari pilot and multi-seed validation are **not run**.
There is no faithful Atari result to report yet. The previous bounded and
never-clear ARROW ports are different protocols, not results of this one.

This protocol transfers the author's **unmodified learning code and normal
substrate configuration** to our original six Atari games. It is not an exact
reproduction of the paper's MiniGrid benchmark, not a verified reconstruction
of the author's unpublished NM512 environment pin, and not a compute/storage
matched comparison against ARROW. These distinctions are machine-readable in
each launch manifest.

## Learning invariants

| Component | This reference protocol |
|---|---|
| World model and ordinary actor/critic | Direct pinned `D.Dreamer` calls, one persistent agent |
| Ordinary replay | Shared dictionary of **all** prior/current real episodes; no current-task filter |
| Sampling | Original NM512 length-weighted episode sampler, seed 0 per generator |
| Normal batch | 16 sequences × 64 steps, not the author's 4 × 16 smoke override |
| Base updates | Train ratio 512: one update per two online decisions, plus 100 initial pretrain updates |
| Imagination | Original RSSM and policy; horizon 15; all 1,024 posterior states become starts |
| Rehearsal | Direct `tunnel_update`, 50 updates **per prior phase** after each complete 2,000-decision chunk |
| Grading | `cont_grading=True`; reach-weighted realized reward; strict `>0.3` bonus of 10; survival-weighted live-critic bootstrap at `feats[-1]` |
| Selection | Original top 25%, 256 selected dreams per update |
| Gradient ownership | Rehearsal updates actor only; ordinary updates still train WM and actor/critic |
| Actor | Shared five-layer one-hot head, unimix 0.01, Adam LR 3e-5; no router or saved task heads |
| Task identity | Scheduler/per-phase replay libraries only, never an observation/model input |

The resolved model is the original NM512 `defaults` merged with the YAML block
in Dream Rehearsal `substrate/SETUP.md`. The source's `value: {layers: 5}` is
unused; NM512 consumes the inherited two-layer `critic`. It is preserved, not
silently renamed. Model defaults, consumed critic settings, unused preset keys,
parameter counts and source hashes are saved with a run.

`ReplayLibraries.finish_phase` uses exactly the newly inserted online-episode
keys since that phase's prefill, matching the author's normal `rehearsal_anchor=0`,
`graduations=1` library. Prefill episodes still enter ordinary shared replay.
Fewer than two own-phase episodes causes an explicit failure rather than the
author's silent omission of a task's rehearsal library.

## Atari protocol and budgets (explicit adaptations)

Task order:

1. `ALE/MsPacman-v5`
2. `ALE/Boxing-v5`
3. `ALE/CrazyClimber-v5`
4. `ALE/Frostbite-v5`
5. `ALE/Seaquest-v5`
6. `ALE/Enduro-v5`

Each task gets **1,474,560 agent decisions including 2,500 random prefill**.
This is 90 × 32 × 512 decisions, not a claim of the paper's MiniGrid duration.
The remaining 1,472,060 online decisions are 736 chunks of 2,000 plus a final
60-decision fragment. Rehearsal is interleaved, not deferred until a 16,384-step
ARROW epoch. The final fragment generates no extra rehearsal event. Collector
state persists across chunks and resets only at a new task. There is no 541st
epoch revisiting task 0.

The MiniGrid common-return `0.6` all-good early stop is **not** applied to
incommensurate Atari reward scales. Task duration is fixed in advance. Evaluation
includes the exact final budget boundary, unlike the original pre-chunk loop
when it exits at its maximum step cap.

Projected complete-run budgets, generated by `OfficialDreamRehearsalConfig.projected_budgets`:

| Counter | Budget |
|---|---:|
| Collected decisions, including prefill | 8,847,360 |
| Random prefill decisions | 15,000 |
| Online decisions | 8,832,360 |
| Ordinary world-model updates | 4,416,280 |
| Ordinary actor updates | 4,416,280 |
| Ordinary critic updates | 4,416,280 |
| Extra actor rehearsal updates | 552,000 |
| Total actor updates | 4,968,280 |

These are **not** the old ARROW port's compute budget. They must not be described
as a storage-only ablation or a matched ARROW comparison. Official batch sizes
and train ratio can be much more expensive on this Atari interaction budget.

### Environment boundary

Gymnasium 1.1.1 / ALE 0.11.1, emulator frameskip 1, full 18-action space on
every task, repeat 4, no sticky actions, up to 30 reset no-ops, RGB 64 × 64
uint8 observations, max pooling/preprocessing from `AtariPreprocessing`.
Rewards remain raw; the **source** Dreamer heads perform their original
symlog distributional learning. No reward clipping, task-conditioned network
or life-loss termination is added. An episode time limit is 108,000 nominal
raw frames (27,000 nominal decisions). ALE also enforces that raw-frame cap,
including reset no-ops, so a capped episode may have fewer than 27,000 agent
decisions. Time limits end episodes but are not MDP terminals.

Separate counters report agent decisions and actual raw emulator frames,
including reset no-ops. Train task `j` is seeded once with `seed + 1000*j`,
evaluation with `seed + 1000*j + 100`, modulo 2^32; subsequent resets advance
the environment RNG. Python, NumPy, torch CPU/CUDA and action spaces are seeded.
The original per-dataset sampler seed is explicitly 0. Original CUDA
nondeterminism is retained and runtime/backend flags are saved.

### Full-history storage

Set `dataset_size=0`, the NM512 no-erasure option. The stock one-million limit
would not be never-clear at this Atari budget. Retention is verified against
the exact collected-transition counter at every evaluation round.

Inactive episode pixel arrays are moved losslessly into one append-only CPU
mmap; active episodes remain appendable and all auxiliary arrays stay in RAM.
Per-phase libraries reference the same episode objects, not additional image
copies. The original sampler is unchanged; deterministic list-backed and
mmap-backed batches are tested byte-equal, including dtypes/reset markers.
Complete and phase-final partial episodes are saved as upstream lossless NPZ
archives. No observation compression/dtype advantage purchases extra samples.

The mmap reserves a worst-case bound for transitions plus reset frames, not a
FIFO capacity. It never overwrites: exceeding the bound fails. Manifests report
the bound, retained samples, array bytes and mmap logical/allocated filesystem
bytes separately. Python/OS/index overhead is explicitly not included in tensor
byte accounting. Replay and evaluation archives have separate paths.

### Evaluation and reporting

Evaluate **all tasks seen so far** before online training and after every chunk,
including the tail. Each evaluation uses 10 episodes and source `training=False`:
actor argmax, **stochastic upstream latent inference**, not a fully deterministic
policy pipeline. Training parameters are frozen during evaluation; transitions
go to separate caches and never enter ordinary replay or rehearsal libraries.

Evaluation temporarily seeds/restores Python, NumPy and torch RNG state; this is
an explicit improvement to isolation, not byte-identical author orchestration.
No evaluation result affects task duration, data selection or optimization.
Evaluation is expensive: 154,980 episodes at the full fixed budget. This count
is generated in every dry-run manifest under
`evaluation_episodes_upper_bound`. Evaluation interaction is separate from
training and not free compute.

The original logger's retained `metrics.jsonl` field `step` means
`4 * cumulative online_agent_decisions`, excluding prefill/reset no-ops. This
mapping is saved in the manifest; use explicit counters in the project JSONL
files for comparisons, not that legacy field. Full evaluation episode archives
also consume disk; the launch-time replay-space check is a lower bound, not a
guarantee that all evaluation outputs will fit.

`evaluation.jsonl` preserves individual raw returns, per-task means/stds, phase,
round and all counters. `summary.json` reports each task's last checkpoint and
the mean of the last three rounds of the last phase separately. No cross-game
raw-return average or “accuracy” is reported. The full matrix supports acquisition,
retention and forgetting; no normalized or transfer claim is inferred here.

### Snapshot and resume limitation

Phase-end model snapshots are atomic and checksummed, **analysis-only**. They
omit optimizer/RNG/environment/sampler state, so they are not resumable training
checkpoints. The runner refuses an existing run directory. A failed run remains
a failed record; it must not be silently restarted or joined to a new run.

## Setup and verification

Use a separate Python 3.10–3.12 environment. Do not `pip install -e .` into it:
the main ARROW package intentionally pins torch 2.3.0, whereas this reference
pins torch 2.4.1. The launcher resolves repository paths and exposes only the
required project modules. Top-level constraints are pinned; full transitive
`pip freeze` and platform details are saved, not claimed to be the authors' lock.

```bash
python3 -m venv .venv/dream-rehearsal-reference
.venv/dream-rehearsal-reference/bin/python -m pip install -r requirements/dream_rehearsal_official.txt
.venv/dream-rehearsal-reference/bin/python -m unittest discover -s tests -p 'test_dream_rehearsal_official.py'
.venv/dream-rehearsal-reference/bin/python -m unittest discover -s tests -p 'test_dream_rehearsal_reference_parity.py'
.venv/dream-rehearsal-reference/bin/python scripts/run_dream_rehearsal_official_atari.py --dry-run
```

Source fixtures use synthetic tensors and optimizer spies, not a ROM run or an
optimizer update. They do not satisfy the required target-accelerator smoke.
Import or acquire Atari ROMs according to ALE's supported setup and your rights;
never add ROMs to Git.

After reviewing/committing/pushing this protocol, fetch and verify a clean synced
checkout. The launcher enforces that provenance **before** environment creation.
First inspect the GPU smoke manifest:

```bash
CUDA_VISIBLE_DEVICES=0 .venv/dream-rehearsal-reference/bin/python scripts/run_dream_rehearsal_official_atari.py --smoke --dry-run
```

Removing `--dry-run` launches a two-task smoke with 5,000 decisions per task,
800-raw-frame episode limits and two eval episodes. Normal model, batch size,
train ratio, grading and rehearsal constants remain unchanged. This altered
duration/evaluation protocol is explicitly classified `smoke`, never a result.
Only after it succeeds should the six-task `pilot` launch be considered. This
document and this implementation change do not start either run.
